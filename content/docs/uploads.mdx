---
title: Browser uploads
description: Upload local files or fetch eligible HTTPS URLs in your browser.
---

The browser uploader uses your DavidApps-backed Seedyn session. It sends bytes
to `/api/uploads` and shows actual transfer progress.

The dialog has one job before a file exists: take the file. Drop it, paste it,
or press **Browse files**. There is no slug field, no domain picker, and no
file-type option to read first — the transfer starts the moment a file arrives,
whether it came from the picker, a drop anywhere in the app, or the clipboard.

Everything optional lives on the step after the upload, where it applies to a
link that already works. That step is shaped by what the server decided the file
is: a PNG, JPEG, WebP, or AVIF offers **Create GIF URL** (encoded in your
browser, stored without a detail-page detour), a rendered page offers **Open
page**, and a format with no extra capability offers nothing extra. Under
**Customise link** you can change the slug and the media domain; ignore it and
you keep a permanent random URL on your account default.

Each library page carries its own entry point — **Upload image** on Images,
**Upload file** on Files, **Upload text** and **New text** on Texts — and the
header keeps a general **Upload** on every page. The per-page buttons narrow the
operating system file picker; the server still classifies whatever it receives,
so a mis-picked file is stored as what it actually is rather than rejected.

URL ingestion happens only in the browser. The URL must be HTTPS, CORS must
allow the fetch, redirects must remain HTTPS, and the streamed bytes must stay
within the upload cap. URLs containing embedded credentials are rejected. The
request omits cookies, authorization, and referrer information; the app CSP
allows arbitrary HTTPS connection destinations solely for this user-selected
fetch and does not broaden script, style, worker, form, or frame sources.
Seedyn does not provide a server-side CORS or SSRF proxy.

Original uploads are capped at 64 MiB. Image and text compatibility endpoints
use a 16 MiB cap.

## Custom public URLs

Every upload gets a permanent random URL immediately. To choose a readable one,
open **Customise link** on the completed upload and type a slug; Seedyn checks
availability as you type. Custom slugs use 3–48 lowercase letters, numbers, and
single hyphens, for example `launch-screenshot`.

Every upload detail page also has a **Public URL** control. Changing the slug
rotates the direct `i.dave.tips` URL immediately, so the previous direct link
stops working. Password protection may perform its own URL rotation when first
enabled. S3 object aliases remain stable and continue resolving to the upload's
current direct URL.

## Media domain

An upload uses the account default unless you say otherwise. When more than one
media domain is configured, **Customise link** offers the alternatives on the
completed upload. Seedyn stores that choice with the upload, so its library,
detail, GIF, and API responses keep presenting the same canonical URL after
account defaults change. Only the presented link changes — the object remains
available by the same slug on every configured Seedyn media domain.

## Sandboxed HTML pages

Save a web page with Cmd+S, upload it, and it is a page. The browser uploader
sends `renderHtml=auto`: Seedyn renders a non-empty UTF-8 HTML document as
`text/html; charset=utf-8` and treats everything else as itself. There is
nothing to tick.

If an installation has no media domain isolated from the app, an automatic
render degrades to a plain download rather than failing the upload. Machine
clients are unchanged — `/api/upload` and the ShareX endpoints still default to
`renderHtml=false` and still reject `renderHtml=true` for bytes that are not an
HTML document.

Rendered pages never enter the authenticated app document. They are served
only from a configured public media domain with an originless CSP sandbox that
blocks scripts, forms, connections, media, frames, objects, workers, and
manifests. Inline CSS and HTTPS/data images are allowed. Password protection
continues to use the normal unlock flow before the sandboxed page is returned.

Member accounts receive 5 GB of storage by default. Original objects and stored
GIF variants both count. The library shows committed usage and any bytes
currently reserved by an upload. Administrators are unlimited and can raise a
member's limit from the admin user ledger. Browser, API, and ShareX uploads all
use the same race-safe quota enforcement and return
`storage_quota_exceeded` when the next object would cross the limit.

## Password protection

Every image, video, text, file, and stored GIF variant can inherit an optional
password from its parent upload. Open the upload detail page to set, change, or
remove it. The detail page shows the current access state; password hashes and
storage keys are never returned to the browser.

Adding a password rotates the public URLs the first time protection is enabled.
Copy the newly displayed URL after saving. Visitors receive a small unlock page
before any uploaded bytes, metadata response, range, or download is served.

## Text, code, and documents

Open **Texts → New text or document** and choose the authoring surface:

- **Code** uses CodeMirror, accepts a local UTF-8 file, records an allowlisted
  language, and renders the owned read view with bounded Shiki highlighting.
- **Document** uses Tiptap's toolbar, Markdown shortcuts, task lists, and `/`
  block menu. It imports and exports Markdown and stores the published object as
  portable `.md`, so the permanent URL is useful outside Seedyn too.

Both modes keep an autosaved browser-local draft until creation succeeds. The
document editor uses Tiptap JSON only for that private editing state; publishing
serializes it with Tiptap's official Markdown support. The authenticated read
view parses the Markdown through the same bounded schema, removes unsafe link
targets, and renders it on the server with Tiptap's static renderer rather than
shipping a read-only editor.

The permanent media URL is the raw consumable form. Authored text objects are
served as `text/plain; charset=utf-8` with `nosniff`; SVG, XML, and JavaScript
are never promoted to executable browser MIME types. For machine clients HTML
stays attachment-only unless they send `renderHtml=true`; browser uploads render
it automatically as described above.

Images, files, and texts use cursor-backed infinite loading. The initial page
is server-rendered and retains real next-page links without JavaScript. Once
hydrated, TanStack Query appends pages; TanStack Table owns table-mode rows and
TanStack Virtual bounds compact-list DOM size for large result sets.

Library rows, cards, tables, and upload details show a durable source badge:
Browser, HTTP API, ShareX, or S3. Machine-created items also show the API-key
Name and immutable identifier. This provenance is written atomically with the
upload record and survives credential rename, revocation, or history cleanup.
