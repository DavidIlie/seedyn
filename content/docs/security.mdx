---
title: Security model
description: Identity, tenancy, public media, and untrusted-file boundaries.
---

DavidApps controls invitation and issues OIDC authorization codes with PKCE,
state, and nonce.
Seedyn persists the issuer and pairwise subject and enforces the current user id
inside every resource query.

DavidApps also signs a per-application role. Exact `app_role=admin` maps to the
Seedyn admin role; malformed, missing, and every non-admin value maps to member.
Email remains display data and never grants `/admin`. Sessions expire after 15
minutes so a changed DavidApps grant is re-evaluated promptly.

The admin ledger is read-only and every cross-user aggregate passes the same
server-side admin guard. Its queries select safe metadata only: no API-key
hashes, OIDC tokens, storage keys, checksums, uploaded bodies, or MinIO
credentials. DavidApps does not expose a supported app-user analytics listing,
so the user count means identities that have signed in to Seedyn.

The MinIO bucket is private. Link and password access goes through the media
handler, which looks up an exact READY slug and extension and derives headers
from trusted database classification. Dangerous or unknown content is
attachment-only; every response is `nosniff`, and the media origin receives no
app cookie. The default media CSP has no script, network, object, or frame
sources and permits forms only so the password unlock can submit.

HTML gains active MIME semantics only through the `renderHtml` upload field:
`true` from a machine client, or `auto` from the browser uploader. Either way
classification requires a non-empty UTF-8 HTML document and the service verifies
that the chosen origin resolves exclusively as a configured media host before
writing storage. `auto` degrades to a plain attachment when it does not, so an
automatic render can never widen the boundary that `true` would have refused
to cross. The
rendered response uses `sandbox` without capability tokens or same-origin,
blocks script, forms, connections, media, frames, objects, workers, and
manifests, and adds noindex, opener isolation, and a restrictive permissions
policy. Inline CSS and HTTPS/data images are the only extra document resources.
The app host continues to return not found for every public asset path.

Optional per-upload passwords are encoded with Argon2id using an independently
generated salt and the OWASP minimum memory-hard profile (19 MiB, two passes,
one lane). Plaintext passwords are never stored or logged. Successful browser
verification produces a signed, 12-hour, `HttpOnly`, `SameSite=Lax` grant scoped
to the exact media path; production grants are always `Secure`. The grant binds
the upload id and password version, so changing or removing a password
invalidates it without storing a bearer token in the database.

Protected `GET`, `HEAD`, and byte-range requests all pass the same grant or
HTTP Basic verification boundary before object storage is opened. Protected
bytes and unlock responses use `private, no-store` and vary on `Cookie` and
`Authorization`, preventing a shared cache from serving one visitor's unlocked
response to another. Password attempts have both source-wide and per-object
Redis ceilings before Argon2 work; if Redis is unavailable, verification fails
closed. The unlock parser accepts only URL-encoded bodies and stops after 2 KiB.

API upload routes authenticate and pass fail-closed Redis source, credential,
and account ceilings before reading multipart bytes. Browser mutations have both
source and account ceilings; GIF validation has a lower account budget and one
active validation slot. The parser uses bounded fields, one file, actual-byte
limits, timeouts, cancellation, stale-file reaping, and temporary files rather
than `Request.formData()`. Object-store writes use 5 MiB multipart streaming and
an abort-aware process concurrency cap, so allowed large uploads cannot all be
buffered in the Next.js process at once.

Upload Route Handlers repeat the app-host boundary themselves and are excluded
from the Next.js Proxy matcher. This avoids Next 16.3's pre-Proxy request clone,
which otherwise buffers bodies and silently truncates them at its configured
cap. Remaining proxied request bodies are capped at 256 KiB.

Upload provenance contains only bounded display metadata: an ingress enum and
snapshots of the authenticated key id, name, and optional owner-managed device
label. Labels are never accepted from an upload request or guessed from a
User-Agent. Raw credentials, hashes, Authorization headers, network addresses,
and S3 signing material are excluded. Snapshot fields intentionally have no
foreign key to prunable key history.

Runtime-protected docs intentionally contain no credentials or operational
secrets because repository visibility is a separate boundary.
