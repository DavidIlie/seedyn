---
title: Serving objects
description: Public URL behavior, caching, ranges, downloads, and deletion.
---

Every completed original and GIF variant receives an application-generated URL
on the selected Seedyn media domain. The current domains are `i.dave.tips`
and `i.gurt.ing`; both resolve the same global slug namespace. The bucket
remains private: the media origin validates the database row and managed MinIO
metadata before streaming any bytes.

## Public by exact link

Media requests do not require a Seedyn session, and responses allow cross-origin
reads. There is no public index, search, or directory listing. A URL must match
the stored lowercase slug and extension exactly; alternate extensions and case
changes return not found.

By default, treat a media URL as a bearer link. Anyone who has it can fetch the
object until its owner deletes the upload. An owner can instead add a password
from the upload detail page. The first time protection is enabled, Seedyn
rotates the original and GIF-variant URLs so the protected object does not reuse
a URL that may already have been cached.

Opening a protected URL returns a non-cacheable unlock page, not the uploaded
bytes. A successful password submission creates a 12-hour, `Secure`,
`HttpOnly`, path-scoped browser grant and redirects to the same URL. Passwords
are sent in the POST body and never appear in the URL. Changing or removing the
password expires every earlier grant.

Non-browser clients can send HTTP Basic authorization with the fixed username
`seedyn`:

```bash
curl --user seedyn -o download.bin \
  'https://i.dave.tips/<slug>.<extension>'
```

`curl` prompts for the password without adding it to shell history. Do not put
passwords in query strings, filenames, command arguments, or shell history.
Protected browser links are intended for direct navigation and embedding after
unlock; cross-origin JavaScript should use a server-side Basic-authenticated
fetch rather than attempting to read a credentialed wildcard-CORS response.

## HTTP behavior

The media origin supports `GET`, `HEAD`, `OPTIONS`, and the small password-form
`POST`, conditional requests with `ETag` and `Last-Modified`, and one byte range
at a time. Unprotected full responses are cached publicly for one hour in a
browser and up to one day in a shared cache. Unprotected range responses are
private and vary on `Range` so an intermediary cannot confuse a partial body
with the complete representation. Every successful protected response,
including `HEAD` and ranges, is `private, no-store` and varies on `Cookie` and
`Authorization`.

Content disposition is recorded with the upload. Safe media may render inline;
other files download with a sanitized form of the original filename. Explicitly
opted-in UTF-8 HTML uses `text/html` and `inline` only on a public media host.
Its CSP creates an originless sandbox and blocks script, form, connection,
media, frame, object, worker, and manifest capabilities; inline CSS and
HTTPS/data images remain available for static documents. Every response uses
`nosniff` and the applicable sandboxed policy.

## Deletion

Deleting an upload removes its original and all generated variants from Seedyn.
The exact public URLs then resolve as not found. A client or intermediary may
retain a previously cached response until its advertised cache lifetime ends,
so deletion is not a recall mechanism for bytes someone already fetched.
The same limitation applies to an old bearer URL when protection is first
enabled: Seedyn rotates the current URL and closes the old one at the origin,
but cannot recall a copy that was fetched or cached before that change.
