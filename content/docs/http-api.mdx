---
title: Upload API
description: Canonical machine-upload request and response contract.
---

## Request

```http
POST /api/upload
Authorization: Bearer <key>
Content-Type: multipart/form-data

file=<binary>
```

Optional `kind` is a hint: `auto`, `image`, `file`, or `text`. Server byte
classification remains authoritative. Optional `renderHtml=true` explicitly
promotes a verified non-empty UTF-8 HTML file to a sandboxed inline page. It is
valid only on the canonical endpoint, requires the `upload:file` scope, and
fails unless the selected media domain is separate from the application host.
Omitting the field keeps HTML attachment-only. `renderHtml=auto` is the browser
uploader's setting: render the file as a page when it really is an HTML
document, otherwise classify it normally, and never fail the upload over it.

## Success

The canonical endpoint returns HTTP 201:

```json
{
  "id": "upload-id",
  "kind": "image",
  "contentType": "image/png",
  "disposition": "inline",
  "renderedHtml": false,
  "url": "https://i.dave.tips/unguessable.png",
  "message": "https://i.dave.tips/unguessable.png"
}
```

The returned origin follows the API key's **Media domain** setting, then the
account default. Changing either setting affects future uploads only.

Errors are JSON with `error.code`, `error.message`, and a safe request id.
Rate-limit responses include `Retry-After`. Dependency failure before body
parsing returns a safe 503.
